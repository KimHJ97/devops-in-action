# GCP 로드밸런서 설정

 - 인스턴스 그룹 생성
 - 고정 IP 생성(외부 고정 IP 주소 예약)
 - 부하 분산 생성
```
# 네이밍 규칙
[프로젝트/서비스명]-[환경]-[리소스유형]-[상세]
 - 서비스명: naver
 - 환경: prod / dev / stage
 - 리소스 유형: lb / ip / fw / neg / backend / hc / cert
 - 상세: https, api, admin, token 등
```

## 인스턴스 그룹 생성

로드밸런서 백엔드 구성시 인스턴스 그룹을 설정해야 한다.

 - 유형: 새 비관리형 인스턴스 그룹
 - 이름: naver-prod-ig-asn3-01
 - 위치: asia-northeast3 (서울)
 - 영역: asia-northeast3-a
 - Network and instances
    - 네트워크: default
    - 서브 네트워크: default
 - VM 인스턴스: naver-prod-vm-chat-asn3-01, naver-prod-vm-chat-asn3-02
 - 포트 매핑
    - 이름이 지정된 포트를 통해 인스턴스 그룹에 트래픽을 전송하려면 이름이 지정된 포트를 만들어 수신 트래픽을 특정 포트 번호에 매핑한 다음 '부하 분산'으로 이동하여 이 인스턴스 그룹으로 부하 분산기를 만듭니다.
    - __단일 인스턴스에 포트별로 여러 개의 서버를 띄운 경우 설정한다.__ (포트 매핑이 필요한 경우)
        - 8080: api
        - 8081: admin


## 외부 고정 IP 주소 예약 (IP 주소 > 외부 예약)

해당 고정 IP는 로드밸런서의 프론트 IP로 사용된다.

 - 이름: naver-prod-ip-lb-public
 - 네트워크 서비스 계층: 프리미엄
 - IP 버전: IPv4
 - 유형: 전역

## 부하 분산

 - `부하 분산기`
    - 부하 분산기 유형: 애플리케이션 부하 분산기(HTTP/HTTPS)
    - 공개 또는 내부: 공개(외부) 인터넷을 통해 클라이언트의 요청을 대상으로 라우팅하는 인터넷 연결 부하 분산기입니다.
    - 전역 또는 단일 리전 배포: 전역. (단일 리전인 경우 단일 리전 선택)
    - 부하 분산기 생성: 
        - 외부 애플리케이션 부하 분산기: 라이언트는 인터넷 어디에서나 이 부하분산기에 연결할 수 있다.  전역/리전 따로 설정이 가능하다. 전역으로 설정하면 단일 Anycast IP가 전세계 여러 지역에 트래픽을 분산한다.
        - 내부 애플리케이션 부하 분산기: 동일한 VPC 네트워크에 있는 클라이언트 또는 VPC 네트워크에 연결된 클라이언트에서만 액세스할 수 있는 내부 IP 주소를 사용한다.
 - `프론트엔드 구성`
    - 이름: naver-prod-lb-fe
    - 프로토콜: HTTPS
    - IP 버전: IPv4
    - IP 주소: 이전에 설정한 외부 고정 IP 선택
    - 포트: 443
    - 인증서: 발급
 - `백엔드 구성`
    - 백엔드 서비스1
        - 이름: naver-prod-lb-be-api-01
        - 백엔드 유형: 인스턴스 그룹
        - 프로토콜: HTTP
        - 상태 확인
            - 이름: naver-prod-lb-status-api
            - 포트: 8080, 제한 시간: 5초, 확인 간격: 5초, 비정상 기준: 2회 시도
        - 백엔드
            - 인스턴스 그룹: 인스턴스 그룹 선택
            - 포트: 8080
    - 백엔드 서비스2
        - 이름: naver-prod-lb-be-admin-01
        - 백엔드 유형: 인스턴스 그룹
        - 프로토콜: HTTP
        - 상태 확인
            - 이름: naver-prod-lb-status-admin
            - 포트: 8081, 제한 시간: 5초, 확인 간격: 5초, 비정상 기준: 2회 시도
        - 백엔드
            - 인스턴스 그룹: 인스턴스 그룹 선택
            - 포트: 8081

 - `호스트 및 경로 구성`
    - 단순한 호스트 및 경로 규칙 -> __경로별 부하분산__
        - 규칙 1(기본)
            - 호스트: 
            - 경로: 
            - 백엔드: naver-prod-lb-be-api-01

        - 규칙 3
            - 호스트: www.naver.com
            - 경로: /admin
            - 백엔드: naver-prod-lb-be-admin-01
    - 단순한 호스트 및 경로 규칙 -> __호스트별 부하분산__
        - 규칙 1(기본)
            - 호스트: naver.com, www.naver.com
            - 경로: 
            - 백엔드: naver-prod-lb-be-api-01

## 요약

 - 도메인 (`google.com`)
    - CNAME 레코드 -> `google.com`, `www.google.com`, `admin.google.com`, `api.google.com`
    - A 레코드 -> 로드밸런서 IP
 - SSL 발급
    - `google.com`, `www.google.com`, `admin.google.com`, `api.google.com` 도메인을 입력하여 발급
 - 로드밸런서 부하 분산
    - `google.com`, `www.google.com` -> VM 설정
    - `admin.google.com` -> ADMIN VM 설정
    - `api.google.com` -> API VM 설정
